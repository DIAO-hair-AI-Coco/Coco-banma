📁 第 4 步：搞清文件都放在哪（教学重点） Where Everything Lives

理解目录结构，才能讲清"数据在哪、怎么备份、怎么彻底卸载"。

① 程序目录（本机：G:\DSH）

内容说明
DeepSeek Harness.exe主程序（约 244 MB，内含完整 Chromium/Electron 运行时）
resources\app.asar应用本体代码（约 116 MB，打包为单一归档文件）
resources\runtime\内置运行时：Node.js、pnpm、Python、CLI 都在这里 ⭐
resources\app-update.yml升级源配置（官方桌面版为 nightly 每夜构建通道）
Uninstall DeepSeek Harness.exe卸载程序

💡 内置运行时版本（取自 resources\runtime\versions.json）：Node.js v24.18.1　·　pnpm v11.7.0

② 用户数据目录（本机：C:\Users\<用户名>\.dsh）

这个目录由环境变量 DSH_HOME 指向。你的配置、会话记录、密钥、日志全在这里。

内容说明
.credentials.yaml🚨 API Key 等凭据（敏感！演示时绝不能投到大屏）
profiles\配置档（本机为 desktop），含插件清单与个性化配置
sessions\全部会话记录（本机已有 181 个文件）
logs\运行日志——出问题先看这里
cache\ / storages\缓存与存储
attachments\你上传的图片、文档等附件
🚨 两条教学红线：
① 演示时绝对不要打开 .credentials.yaml——里面是你的 API Key，投到大屏等于公开钱包密码。
② 电脑要借给别人 / 要卖之前，先删掉这个文件。

🗑️ 卸载与彻底清理 Uninstall & Clean Up

1

运行卸载程序

在安装目录里运行 Uninstall DeepSeek Harness.exe。

2

手动删除用户数据目录

删除 C:\Users\<用户名>\.dsh。卸载程序通常不会删它——不删的话 C 盘空间不会释放。

⚠️ 删之前先备份！删掉 .dsh 就等于丢掉所有会话记录和配置，无法恢复。 要留就先把整个目录复制到 U 盘或移动硬盘（注意它含 .credentials.yaml，不要放公共网盘）。

安装方式二 · npm 命令行详解PATH B: NPM — 每一步都有真实截图

📌 本页是全课程最"手把手"的一页。下面每一步都配真实的终端截图（内容来自本机实际执行）， 包括出错时的报错原文——这样你在自己电脑上遇到同样问题时，能立刻认出它。

🎯 先决定：用 npx 还是 npm install -g？ Two Ways, Pick One

⭐ 方式 A：npx（官方推荐）
  • 命令：npx @deepseek-ai/dsh web
  • 不需要全局安装，直接运行
  • npx 自动下载到缓存，不污染全局目录
  • 官方 README 主推这条
  • 缺点：每次可能要检查更新，首次较慢
方式 B：npm install -g
  • 命令：npm install -g @deepseek-ai/dsh
  • 装成全局命令，之后随处可用 dsh
  • 适合要反复使用的老师
  • 实测：536 个包 / 3 分钟 / 453 MB
  • 缺点：会占用全局环境
不推荐：源码编译
  • git clone + pnpm install + pnpm run build
  • 只适合要改 DSH 源码的开发者
  • 教学场景完全用不到
  • 编译耗时长、依赖多、容易失败

📖 方式 A 来自官方 README（github.com/deepseek-ai/deepseek-harness）。
方式 B 为本机实测——注意：社区资料曾提到某些环境下 npx 装不上，改用全局安装才成功。两种都列出来，你有退路。

🖥️ 方式 B 实战：npm 全局安装（逐步截图） Step by Step, Real Terminal Captures

以下 6 步全部在本机真实执行过。截图里的版本号、包数、报错都是真的。

1

检查环境：Node 与 npm 在不在、版本够不够

在终端里敲：

node --version
npm --version

版本要求：^22.19.0 || >=24.0.0。本机是 v24.20.0，满足。

⚠️ 没装 Node 怎么办？去 nodejs.org 下载 Windows 安装包， 安装时务必保留「Add to PATH」勾选项；装完后必须新开一个终端窗口再验证——老窗口读不到新环境变量，这是新手最常见的"我明明装了却说找不到"。
2

执行全局安装

npm install -g @deepseek-ai/dsh

然后等着。实测要下载 536 个包，耗时约 3 分钟。

🔍 为什么会有 5 条 install-scripts 警告？
较新版本的 npm 出于安全考虑，默认不执行第三方包的安装脚本，需要你显式放行。 涉及 node-pty（终端模拟）、koffi（原生调用）、protobufjs 等。 本机实测：不放行也能正常启动 Web 界面；只有当某个功能（比如终端交互）报错时，再按提示放行即可。
3

验证"装上了没有"——这一步千万别跳过

dsh --version

为什么要单独验证？为了把"安装失败"和"启动失败"分开排查。如果这一步就报错，说明装的问题；如果这步过了、下一步报错，说明是配置或环境的问题。分开排查能省一半时间。

4

看一眼它到底能干什么（很有教学价值）

dsh --help

这一步会揭示 DSH 的 profile（配置档）体系——这是理解它怎么工作的关键。

1
dsh web——启动浏览器界面（本课主要用这个）。等价于 dsh --profile web。
2
dsh tui——启动终端界面，不开浏览器。适合服务器环境。
3
dsh headless "任务"——一次性执行一个任务，打印结果就退出。适合做自动化、批量处理。
4
dsh rescue --from-default-profile web——当配置被玩坏了，用官方模板重建一个"救援"配置档。这个设计非常贴心。
💡 教学价值：dsh --help 的输出本身就是最好的"产品说明书"。 教学生"遇到新工具先看 --help"，比教他们背命令有用得多。
5

看 web 界面有哪些启动参数

dsh --profile web --help
6

启动 Web 界面

先建一个工作文件夹（重要——后面讲工作区时会解释为什么），在里面启动：

# 建目录并进入
mkdir dsh-first-agent
cd dsh-first-agent

# 启动
dsh web
🚨 新手最容易犯的错：把终端窗口关了。
网页只是界面，服务跑在终端里。关掉终端 = 关掉服务 = 网页立刻打不开。 这个终端窗口要一直开着，最小化可以，关闭不行。

⭐ 方式 A 实战：官方推荐的 npx（更省事） The Officially Recommended Way

如果你只是想用一次，或者不想让全局环境变脏，用这条。官方 README 主推的就是它。

# 官方 README 的原话命令
npx @deepseek-ai/dsh web
🔍 npx 和 npm install -g 的区别，一句话讲清：
npx = "临时借来用一下"（下载到缓存，不进全局目录）；
npm install -g = "正式装在我电脑上"（进了全局目录，随处可用）。
两者都要下载同样的 536 个包，只是放的位置和管理方式不同。

🐛 真实踩坑：装插件时提示 'pnpm' is not recognized A Real Error We Hit

这一节是本课最有价值的部分之一——因为你在自己电脑上一定会遇到它。

尝试管理插件时：

dsh plugin --profile web --help
1
为什么会报错？DSH 的插件管理用的是 pnpm（一个比 npm 更快、更省磁盘的包管理器），而 pnpm 不在 Node.js 的安装包里，要单独装。
2
怎么解决？单独装一个 pnpm：npm install -g pnpm（本机实测几秒钟就装完）。
3
重要区分：只是启动 Web 界面的话，根本不需要 pnpm。只有"安装/管理插件"这个动作才需要。别因为这个报错就以为整个安装失败了。
🎓 把报错变成教学素材：这类"依赖缺失"是 IT 行业最常见的故障类型。 遇到报错时教学生的正确动作是——① 完整读报错信息（它往往直接给了解决办法）② 复制报错关键词去搜 ③ 判断这个功能到底是不是我现在必须的。 第 ③ 条最容易被忽略，也最能省时间。

首次使用 · 界面、权限与安全FIRST RUN — WORKSPACE, PRESETS & PERMISSIONS

🖥️ 界面长什么样 The Three-Column Layout

┌──────────────┬─────────────────────────────┬──────────────┐
│  工作区文件树  │      对话 / 任务过程          │   模型与设置   │
│  会话列表     │      输入框                  │              │
└──────────────┴─────────────────────────────┴──────────────┘

📎 界面布局会随 nightly 版本变化。教"每一栏是干什么用的"，不要教"按钮在屏幕第几个位置"——位置下个月就变了。

⭐ 新手最容易卡住的地方：工作区 Workspace — The #1 Newbie Blocker

现象：输入框是灰色的，点不动、打不了字。
原因：没有选中工作区。这是 90% 的新手遇到的第一个问题。

工作区（Workspace）不是"聊天分类"，而是文件边界。

✅ 你必须主动做的事
  • 添加一个工作区（比如 D:\dsh-first-agent）
  • 并且选中它
  • 输入框变亮 = 可以用了
💡 一句话类比
  • 工作区就像给 AI 划了一个"可以进出的房间"
  • 房间以外的文件，它原则上碰不到
  • 这个类比学员一听就懂
🚨 为什么这是安全边界
  • AI 能读写哪些文件，由工作区决定
  • 所以不要把工作区设成整个 C 盘
  • 也不要把重要资料所在的文件夹设成工作区

💬 会话管理与 Fork Sessions & Fork

  • 会话保存的不只是聊天记录。它保存了完整操作过程——AI 读过哪些文件、执行过哪些命令、改过什么，都在里面。这既是复盘工具，也是安全审计依据。
  • 可以重命名、搜索、恢复、归档。归档 ≠ 删除——归档只是收起来，数据还在。Archive is not delete.
  • Fork（分叉）：从一个中间点分出一个新会话。⭐ 这是最好的教学演示功能——同一个问题用两种不同问法，Fork 出两个会话对比结果。直接从某一轮分出新会话，原会话不受影响。
  • 对话太长用 /compact 压缩上下文。因为模型的上下文窗口是有限的，历史太长会"挤掉"前面的内容。类似给对话做一次摘要归档。

    • 🎛️ 四种预设（Preset）：决定"这个会话有哪些工具" Four Presets

    "预设"决定的不是"AI 多聪明"，而是"这个会话手里有哪些工具"。

    模式工具集什么时候用
    标准模式完整 Agent：文件编辑、Shell、文件/网页检索、Skills、计划、目标、子 Agent、工作流日常首选，拿不准就选它
    PTC 模式标准全部能力 + 模型可用 TypeScript 编排多步工具调用步骤多、工具调用密集的任务
    极简模式只有持久 Bash + str_replace_editor 两个工具基准测试、教学、观察模型
    创造模式标准能力 + 运行时检查、插件实验、预设创作扩展开发；权限高，别指向重要工作区

    📎 预设的功能描述参考社区资料（dshbase.com，非官方）并与本机实测一致的部分交叉验证；实际工具清单随版本变化，以你安装的版本为准。

    🚨 最容易讲错的一点：计划模式不是第五种预设 Plan Mode Is NOT a Fifth Preset

    预设（Preset）
    • 决定"会话里有什么工具"
    • 标准 / PTC / 极简 / 创造
    • 相当于给你一套什么样的工具箱
    计划模式（/plan）
    • 决定"AI 先出方案还是直接动手"
    • 是一个开关，不是一种模式
    • 相当于先画图纸还是直接开工
    ⭐ 两者的关系
    • 正交——可以任意组合
    • 比如"极简模式 + 计划模式"也能成立
    • 把这两件事混为一谈是最常见的教学错误
    🎯 推荐给学员的第一个正式项目组合：
    标准模式 + 只读权限 + 计划模式
    ——先让 AI 只调查、不动手，把方案讲给你听，你确认了再放开权限。 这是把风险降到最低、又能学会用法的组合。

    🔐 三级权限（安全的核心） Three Permission Levels

    权限含义风险
    Read Only 只读只能看，不能改最低 —— 新手默认用这个
    Workspace Write 工作区写入能在工作区内写文件中 —— ⚠️ 注意：它只限制"写入边界"，AI 仍可能读到工作区之外的内容
    Full Access 完全访问几乎不受限最高 ⚠️
    🚨 必须纠正学员的一个直觉误区：
    Full Access 不是"高级版"，而是"风险最高的选项"。
    权限越高 ≠ 越强，只等于 "AI 出错时能造成的破坏越大"。
    官方安全须知里明确写了："Run the project with the least privileges and access required."（用最小必要权限运行）

    🌳 知识树 Deploying DSH

    🤖 DSH 的部署
    它是什么 What It Is
    • 开源 agent harness（智能体运行时） 不是模型，不是聊天壳
    • 一切皆插件 everything-is-a-plugin 连 Web 界面、计划模式都是插件
    • 底层基于 Cordis 插件框架
    • 许可证 MIT 开源可商用
    • developer preview ⚠️ 官方声明"会有破坏性变更"
    两条安装路径 Two Paths
    • 桌面版 自带 Node，双击即用，推荐教师
    • npm 命令行 536 包 / 3 分钟 / 453 MB（实测）
    • npx @deepseek-ai/dsh web ⭐ 官方 README 推荐
    • npm install -g @deepseek-ai/dsh 装成全局命令
    • 系统要求 Windows 10+ / macOS 13+（Apple 芯片）
    启动与使用 Run & Use
    • dsh web 浏览器界面（默认 127.0.0.1:3080）
    • dsh tui 终端界面
    • dsh headless "任务" 一次性执行并退出
    • dsh rescue 配置坏了用它重建
    • 工作区 = 文件边界 ⭐ 输入框灰了先查这里
    • 会话 / Fork / /compact 管理层上下文
    安全与维护 Safety
    • 四级预设 标准 / PTC / 极简 / 创造
    • 计划模式 ≠ 预设 两者正交，可任意组合
    • 三级权限 只读 / 工作区写入 / 完全访问
    • ~\.dsh 目录 配置、会话、密钥都在这
    • 备份只需备份 ~\.dsh 但含密钥，别放公共网盘
    • nightly 通道 ⚠️ 演示前不要升级
